# 分数口径改进清单（module-035 候选）

> 本文档汇总项目检索/记忆系统中的"分数语义"问题，作为下一个模块（module-035）的候选。
> 根因：**用错了尺子**——把"相对排名信息"当"绝对质量判断"用，或反之。

---

## 一、核心认知：两种分数语义

| 语义 | 回答的问题 | 特征 | 适合场景 |
|------|-----------|------|----------|
| **相对分（排名）** | "谁比谁高" | 只在本批次内可比，跨查询不可比 | 排序取前 N、跨通道融合（抗尺度/抗饱和） |
| **绝对分（质量）** | "够不够好" | 跨查询可比，有绝对阈值含义 | 去重、过滤、档位判断、阈值 |

**错误示范**：拿相对分当绝对阈值用（当前动态 K 的 bug）；拿绝对分当相对序用（少见）。
**隐患**：排序截断 `[:K]` 不设绝对下限 → 本批"相对最高但绝对很烂"的也被注入。

---

## 二、问题清单（按严重度）

### P1：动态 K 用相对分当绝对阈值 → 恒 K=1
- **位置**：`ai_service/rag/memory.py` recall / recall_short → `_dynamic_k`
- **根因**：avg 来自 `hybrid_score`（min-max **相对**归一化，retriever.py L517 注释"跨查询不可比"），套 0.85/0.75 **绝对**阈值
- **后果**：候选 ≥3 时 avg 必跌破 0.75 → 恒 K=1，K=5/3 档死代码；高质量记忆注入不足
- **修法**（方案 A）：动态 K 改用 embedding 绝对余弦（L2 归一化点积），与去重口径统一
- **加防**：返回时按绝对相似度过滤（低于阈值丢弃），防"本批低分上榜"

### P2：检索 min_score 阈值失真
- **位置**：`main.py` chat_stream 的 `MIN_SCORE = 0.3`
- **根因**：拿相对归一化后的 hybrid_score 当绝对 0.3 阈值 → 语义失真（同上）
- **后果**：relevant_count 统计不准；若用于过滤会误放/误杀
- **修法**：改用绝对相似度（嵌入余弦）或去掉该阈值语义

### P3：三通道融合量纲不可比（backlog，module-030 记录）
- **位置**：`retriever.py` `hybrid_score = alpha*fts + (1-alpha)*vector`
- **根因**：min-max 后 FTS/向量分数虽都在 [0,1] 但**分布不同**（向量高密度、FTS 稀疏），直接加权在语义上"权重失衡"；且图谱通道（module-021 的 graph_score）同样量纲
- **后果**：融合权重意义含糊，文档实际排序可能被某通道主导
- **修法**：方案 A = 各自 min-max + 加权（现状，但明确权重语义）；方案 B = **RRF 排名融合** `1/(k+rank)` 天然规避量纲（更稳）

### P4：重排分数饱和（backlog，module-030 记录）
- **位置**：`reranker.py` bge 输出 sigmoid 全接近 1.0（0.9999/0.9998）
- **根因**：CrossEncoder sigmoid 饱和
- **后果**：分数不能当绝对阈值；排序仍正确但区分度低
- **修法**：用原始 logits 替代 sigmoid；需 golden_retrieval A/B 验证

### P5：记忆去重阈值 0.95 校准（module-033/034 观察）
- **位置**：`memory.py` `memory_dedup_threshold = 0.95`
- **根因**：真实 bge-m3 同义改写 cosine≈0.88 < 0.95，不触发去重
- **后果**：措辞变化时"二次同义对话→不膨胀"不成立，记忆缓慢膨胀
- **修法**：下调至 ~0.85（配合方案 A 的绝对相似度口径）

## 三、项目决策表（排名 vs 质量）

| 场景 | 应使用 | 现状 | 问题 |
|------|--------|------|------|
| 三通道融合（FTS/向量/图谱） | **排名（RRF）** | 加权（min-max+alpha） | ⚠️ 量纲不可比（P3） |
| 重排取 top-K | **排名** | 排序 | ✅ 正确 |
| 知识库检索返回文档 | **排名** | 排序 | ✅ 正确 |
| 记忆去重 | **质量**（绝对 cosine） | embedding cosine | ✅ 方向对，阈值待校（P5） |
| 动态 K 档位 | **质量**（绝对相似度） | 相对分 | ❌ bug（P1） |
| 检索 min_score 过滤 | **质量** | 相对分 | ⚠️ 失真（P2） |
| 反思 sufficient | **质量** | 未用绝对分 | ⚠️ 待明确 |

## 四、建议执行方案

**module-035 记忆/检索分数口径校准**（一次收敛）：

1. **统一记忆分数口径**（P1+P5，同根因）：recall/recall_short 动态 K + 去重阈值都改用**绝对 embedding 余弦**；动态 K 三档语义回归（>0.85→5 / 0.75-0.85→3 / <0.75→1 真实可达）；去重阈值 0.95→0.85
2. **min_score 校准**（P2）：chat_stream 的 MIN_SCORE 改绝对余弦或调整语义
3. **三通道融合评估**（P3，可选）：golden_retrieval 跑 RRF vs 加权 A/B，用 Hit@k 量化决策
4. **重排 logits 校准**（P4，可选）：同 golden_retrieval A/B

**验证**：全量 pytest 回归 + golden_retrieval（Hit@k/MRR）对比 + 真实 E2E（记忆注入条数恢复多档）
