## 2. 需求描述

### 2.1 需求来源

- 来源类型：记忆三件套（032/033/034）完成后系统复盘 + 用户确认
- 根因（`score-issues.md`）：**拿相对分（min-max 排名信息）当绝对阈值（质量判断）用**
  1. 动态 K 用 `hybrid_score`（相对归一化）套 0.85/0.75 绝对阈值 → **恒 K=1**，K=5/3 档死代码
  2. 去重阈值 0.95 对真实同义改写（cosine≈0.88）不触发 → 记忆膨胀
  3. chat_stream 的 MIN_SCORE=0.3 同为相对分 → 阈值失真
  4. （可选）三通道融合量纲不可比 → RRF 候选

### 2.2 用户故事

```
作为 记忆系统使用者
我想要 动态 K 真正按质量召回多档、去重能识别同义改写、阈值语义正确
以便 高质量记忆多注入、记忆库不膨胀、过滤阈值可信
```

### 2.3 验收场景（BDD 格式）

```
场景 1：动态 K 多档可达
  假设 有高质量记忆候选（绝对余弦 >0.85）
  当 recall
  那么 召回 5 条（K=5 档真实可达，不再恒 K=1）

场景 2：绝对相似度口径
  假设 候选平均绝对余弦 0.78
  当 recall
  那么 触发 3 条档（0.75-0.85 → K=3）

场景 3：低分过滤
  假设 候选绝对余弦 <0.4
  当 recall
  那么 丢弃（不注入"本批相对高但绝对烂"的记忆）

场景 4：去重阈值校准
  假设 同义改写记忆（真实 cosine≈0.88）
  当 save
  那么 触发去重（阈值 0.95→0.85），更新而非新增

场景 5：min_score 校准
  假设 chat_stream 检索
  当 统计 relevant
  那么 MIN_SCORE 语义正确（绝对口径或去除）
```

### 2.4 非功能需求

| 兼容 | memory.save/recall 签名不变；chat/stream 端点不变 |
| 零回归 | 长期/短期/会话三层行为不回退（278 基线） |

## 3. 技术方案

### 3.1 涉及文件

| 文件路径 | 操作类型 | 说明 |
|----------|----------|------|
| `ai_service/rag/memory.py` | 修改 | 动态 K 改绝对余弦 + 低分过滤；去重阈值默认改 0.85 |
| `ai_service/rag/embeddings.py` | 复用 | embedding 绝对余弦（L2 归一化点积） |
| `ai_service/main.py` | 修改 | chat_stream MIN_SCORE 校准 |
| `ai_service/src/config.py` | 修改 | 去重阈值默认 0.95→0.85；新增低分过滤阈值 |
| `ai_service/rag/retriever.py` | 可选 | 三通道 RRF 融合（P3，评估后决定） |
| `ai_service/tests/test_memory.py` | 修改 | 动态 K 绝对口径测试更新 |
| `ai_service/tests/test_retriever_rrf.py` | 新增 | RRF 融合单测（若实施 P3） |

### 3.2 业务逻辑说明

#### 功能 1：动态 K 改绝对余弦（P1，核心）

```
现状：avg 来自 hybrid_score（min-max 相对分），套 0.85/0.75 绝对阈值 → 恒 K=1
修复（recall / recall_short）：
  1. 对 query 嵌入（embedding_service.embed_text，L2 归一化）
  2. 候选记忆子块 embedding 已在库（存时 L2 归一化，点积=cosine）
  3. 每条候选算绝对余弦 = dot(query_emb, doc_emb)
  4. avg = 候选绝对余弦均值 → _dynamic_k 判定（>0.85→5 / 0.75-0.85→3 / <0.75→1）
  5. 低分过滤：绝对余弦 < memory_recall_min_score（默认 0.4）的候选丢弃
     （防"本批相对高但绝对烂"注入）
  6. 排序仍按绝对余弦降序

与去重同口径：都用绝对 embedding 余弦（去重阈值 0.95→0.85）
```

#### 功能 2：去重阈值校准（P5）

```
config.memory_dedup_threshold: 0.95 → 0.85
理由：真实 bge-m3 同义改写 cosine≈0.88，0.95 太严导致漏去重
降后：同义改写触发去重（更新旧记忆而非新增）→ 记忆库不膨胀
```

#### 功能 3：min_score 校准（P2）

```
chat_stream 的 MIN_SCORE = 0.3：
  现状：作用于相对归一化的 hybrid_score，语义失真
  修复：改为绝对余弦口径（query 嵌入 vs 候选），或移除该阈值只做统计展示
  （relevant_count 用于 UI 展示，不影响回答正确性，故校准语义即可）
```

#### 功能 4（可选）：三通道 RRF 融合（P3）

```
评估后决定：hybrid 模式融合从"min-max 加权"改为 RRF 排名融合
  score = Σ 1/(k + rank_channel)   （k=60）
  天然规避量纲（FTS/向量/图谱分数分布不同）
用 golden_retrieval（Hit@k/MRR）A/B 对比：加权 vs RRF
若 RRF 不劣于现状 → 采纳；否则保持现状并记录
```

### 3.3 关键设计决策

| 决策 | 说明 |
|------|------|
| 记忆统一绝对余弦口径 | 动态K / 去重 / 低分过滤同尺子，语义一致 |
| 低分过滤阈值 0.4 | 参考 19-Agent记忆管理"相似度<0.75 是噪音"的下限保守化 |
| 去重阈值 0.85 | 真实模型实测（同义改写 0.88 附近），平衡漏去重/误合并 |
| RRF 走评估 | 不盲目替换融合，用 golden A/B 量化后决策 |

### 3.4 异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 嵌入失败（query 嵌入） | 降级用原 hybrid_score 排序（不回退失败） |
| 无候选 | 返回空（同现状） |
| RRF 评估 embedding 不可用 | 跳过 A/B，保持现状 |

### 3.5 跨模块契约

```
- memory.save/recall 签名不变（内部口径改）
- recall 返回格式不变（content/score/title/created_at）
- chat/stream 端点签名不变
- 三层 source 分层不变（module-034）
- 匿名降级不变
```


### 4.3 失败诊断方法

| 失败现象 | 可能原因 | 排查步骤 |
|----------|----------|----------|
| 动态 K 仍恒 1 | 绝对余弦没算对 | 检查 query 嵌入 + 点积 |
| 去重过度 | 阈值降太低 | 检查 0.85 是否误合并 |
| 回归失败 | 断言依赖旧相对分 | 更新 test_memory 断言 |

## 6. 风险点与注意事项

### 6.1 已知风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 绝对余弦计算多一次嵌入 | 延迟略增 | 中 | query 嵌入快；候选嵌入已存库 |
| 阈值 0.85 误合并 | 不同事实被合并 | 低 | 可配；E2E 验证 |
| RRF 改变排序 | 检索质量波动 | 中 | golden A/B 量化，不劣才采纳 |

### 6.2 技术注意事项

- [x] query 嵌入用 embedding_service.embed_text（L2 归一化，点积=cosine）
- [x] 候选子块 embedding 存库时已 L2 归一化（module-033）
- [ ] 去重阈值 0.85 用真实同义改写验证
- [ ] RRF 走 golden_retrieval A/B

### 6.3 开发建议

- 先动态K 绝对余弦（P1，核心）→ 去重阈值（P5）→ min_score（P2）→ RRF 评估（P3 可选）
