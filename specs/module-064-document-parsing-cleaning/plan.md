## 2. 需求描述

### 2.1 问题（代码实测）

- 前端只开放 `.md/.txt`；后端只认 `.pdf`（PyMuPDF）；前后端割裂；Word/Excel/PPT/EPUB/CSV 无支持
- 入库链路无独立清洗层；PDF 内嵌图片信息丢失

### 2.2 验收场景（BDD）

```
场景 1：多格式上传
  假设 上传一个 .docx / .xlsx / .pdf
  当 POST /ai/rag/documents/upload
  那么 解析为 Markdown → 清洗 → 分块 → 入库；文本非空；前端 accept 已开放

场景 2：清洗不误伤
  假设 文档含代码块 + 表格 + URL
  当 清洗层处理
  那么 代码块符号/表格结构/URL 不被清洗破坏（白名单哲学）

场景 3：完全重复文档
  假设 上传与已有文档内容完全相同的文件
  当 入库去重
  那么 直接丢弃（content_hash 命中），不重复入库

场景 4：语义重复不删
  假设 上传与已有文档语义重复（cosine≥0.95）但措辞不同
  当 入库去重
  那么 不删除，标 duplicate_cluster_id + canonical 选择；检索只出 canonical
```

### 2.3 范围

**做**：WP1 AnyDoc 解析层 / WP2 五步清洗 / WP3 无损归一化 / WP4 PDF 图片三层开关 / WP5 原件留存 / WP6 去重三级 / WP7 测试文档。
**不做**：OCR/VLM/MinerU 模型实际下载启用（默认关，仅开关+路由框架）；SimHash-LSH 实现（文档量几千+才上，接口预留）；语义修复的 LLM 级（规则先）。

## 3. 技术方案（详见 task-brief §三）

| WP | 方案 | 通过标准 |
|----|------|----------|
| WP1 解析层 | AnyDoc 集成（统一 GFM Markdown，格式识别读字节）+ PyMuPDF 回退；main.py:911 接入；前端 accept 开放 | 多格式上传冒烟非空入库；错误格式明确提示 |
| WP2 清洗层 | 五步（格式清理/冗余过滤/结构恢复⭐/语义修复/分块准备），**按块类型白名单** | 清洗单测含代码块/表格/URL 不误伤；chunker 输出结构零破坏 |
| WP3 归一化 | 无损（NFKC/去零宽/统一空白/表格保持 MD/超长截断） | 归一化单测；不改语义 |
| WP4 PDF 图片 | L1 OCR / L2 VLM / L3 MinerU 三层开关+路由，全默认关，图片价值过滤 | 开关+占位符替换单测；默认关不报错 |
| WP5 原件留存 | 原件落盘 + documents.original_path 列（init_db 幂等 ALTER + migrate_module064.py） | 原件在 + original_path 落库；重灌可用 |
| WP6 去重 | 内容哈希（复用 content_hash）/ 文档级 embedding 余弦≥0.95（标 cluster + canonical）/ SimHash 接口预留 | 三级单测；124 篇冒烟不破坏 |
| WP7 收口 | 测试 + 文档 + ADR-0014 ✅ + 记忆三件套 | 951+N 全绿 |

## 4. 风险与注意

| 风险 | 缓解 |
|------|------|
| AnyDoc 安装失败（依赖/Rust） | 如实记录，评估降级（PyMuPDF 多格式扩展或 pip 版本）；不硬装 |
| 清洗误伤代码/表格/URL | 白名单哲学（按块类型），单测锁定 |
| 扫描版 PDF 无 OCR | 诚实返回"图片未解析"提示；OCR 默认关 |
| 去重误判（Boilerplate 主导相似度） | 先剥离套话再相似度；同源内语义去重 |
| 存量 md/txt/pdf 行为回归 | PyMuPDF 回退保留；存量测试零改动 |
