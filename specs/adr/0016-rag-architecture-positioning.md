# ADR-0016：项目 RAG 架构定位、优缺点与演进路线

## 元信息

- 状态：✅ **已记录**（2026-08-15；作为项目类型定位的权威锚点，面试/简历引用以此为准）
- 日期：2026-08-15
- 关联：ADR-0012（工具治理）、ADR-0015（多轮意图路由，module-063）、module-064（多格式解析）、ADR-0007（记忆进化）、README/METRICS（对外口径）

## 背景：为什么需要这个 ADR

项目经过 62+ 模块迭代后，功能已超出"普通 RAG"范畴，需要一份**类型定位文档**回答三个问题：① 我这个系统到底属于哪种 RAG？② 相对其他类型优缺点是什么？③ 以后往哪升级？——避免面试/简历口径漂移，也给未来演进留锚点。

## 决策 1：当前类型定位 = Agentic RAG（Modular 架构 + Advanced 检索链）

**一句话定位**：

> 本项目是 **Modular RAG 架构下的 Agentic RAG 实现**：检索链路达到 Advanced RAG 水准（查询改写 + HyDE + 三通道 RRF + 语义重排），Agent 编排层让 LLM 自主决定检索/工具/停止（ReAct + 10 工具 + 反思重检），叠加记忆进化与幻觉检测。

**三层对位（代码实测证据）**：

| 分类档 | 定义 | 项目对应实现 | 证据 |
|---|---|---|---|
| Naive RAG | Retrieve→Read 直线 | — | ❌ 远超 |
| **Advanced RAG** | 检索前处理（改写/HyDE）+ 检索后处理（重排） | 分诊式改写 + HyDE + bge-reranker 精排（250 截断） | ✅ 命中率 0.9905 |
| **Modular RAG** | 模块可插拔、可编排（DAG） | 改写/检索/重排/反思/记忆独立模块 | ✅ `retrieval_fusion_mode` 三档开关 + rerank 真实替换（Qwen3→bge，module-030） |
| **Agentic RAG** | LLM 运行时自主决策（是否检索/调哪个工具/何时停） | ReAct 10 工具 + 阶段切分 + 反思充分性→自主重检 | ✅ ctx.phase 状态机（module-058 WP-E） |
| Self-RAG | 自反思检索（微调反射 token） | 反思充分性 + 重检循环（**轻量版**：提示词实现非微调） | ⚠️ 部分 |
| CRAG | 纠错式检索（评估→重试/兜底） | 反思不充分→改写重查 + 多级降级链 | ⚠️ 近似 |
| Memory RAG | 状态化记忆 | 三层记忆 + 进化 v2（类型化衰减/冷降权/冲突消解） | ⚠️ 部分 |
| Adaptive RAG | 按复杂度路由 | 意图路由（知识库/闲聊/实时）——**缺复杂度分级** | ⚠️ 半程 |
| GraphRAG | 知识图谱 + 社区摘要全局查询 | 图谱通道（三通道之一）——**缺社区检测/全局查询** | ⚠️ 部分 |

**主导特征判定**：核心决策点在 LLM 运行时（反思重检、工具选择），故主标签为 **Agentic**；Advanced/Modular 是定语。

## 决策 2：相对其他 RAG 类型的优缺点

| 对比对象 | 本项目的优点 | 本项目的缺点 |
|---|---|---|
| vs **Naive RAG** | 检索质量碾压（0.9905 vs 常规 0.6-0.8）；有反幻觉、有记忆 | 复杂度高、维护成本大（Naive 简单直接） |
| vs **Advanced RAG** | 多了 Agent 编排层（自主重检/工具调用）和记忆进化 | Advanced 更轻量，单轮问答时本项目延迟更高（3-5s） |
| vs **纯 Modular RAG** | 不只是模块化，还有 Agent 决策层 | 模块间耦合比纯 Modular 高（engine 编排） |
| vs **GraphRAG（微软）** | 轻量（图谱只做三通道之一，不建社区摘要）；中文知识库够用 | 全局性问题（"库的主题是什么"）答不了——GraphRAG 的社区摘要优势 |
| vs **Self-RAG** | 不用微调模型（提示词实现反思），成本低；可观测性更强 | 反思判断靠 LLM prompt，不如 Self-RAG 训出来的稳定（无 reflection token 校准） |
| vs **CRAG** | 已有降级链 + 重检兜底 | 无"检索评估器显式打分→触发 Web 搜索"的明确 CRAG 结构 |
| vs **Adaptive RAG** | 意图路由已有（知识库/闲聊/实时） | 无复杂度分级——简单问题也走全检索，浪费 token |
| vs **专用大厂方案** | 全链路自研、全本地离线、可解释 | 无分布式、无多租户、单机规模 |

## 决策 3：项目特点（区别于普通 RAG 的 5 个独有特征）

1. **评估驱动**：112 题 golden + eval_runs 版本化回归 + 消融实验（图谱 +0.24、RRF +0.0191 均实测确认后才放行）——"改坏能发现、改好有证据"
2. **诚实工程**：NLI kappa 0.52 未达标如实标注、记忆冲突 Precision 1.0/Recall 0.5 保守启用、改写 MRR 为负不硬吹
3. **全链路自研 + 框架工具层**：核心编排手写（ReAct/检索/记忆/路由），LangChain 仅工具层（分块器/LLM 适配），LangGraph 实验对照（module-030 行为对齐实测）
4. **中文场景深耕**：jieba 中文 FTS 复活、中文 NLI 实测、中文语气词路由（module-063 规划）
5. **生产级可靠性**：时限预算/级联超时/多供应商降级链/身份隔离双保险/可观测性 trace

## 决策 4：演进路线（按主线，不散点堆功能）

**主线：路由体系**（意图路由 → 多轮路由 → 自适应复杂度路由）

| 阶段 | 内容 | 状态 |
|---|---|---|
| ① 意图路由 | 知识库/闲聊/实时（L4 分类器 449 条） | ✅ 已实施（module-056） |
| ② 多轮意图路由 | 省略句/指代句继承（classify 加 history） | 📋 module-063 待执行 |
| ③ **Adaptive RAG 复杂度路由** | 简单问题不检索直答 / 中等单步 / 复杂多步；复用 L4 分类器模式训复杂度分类器 | 🔬 下一步（补 A 路径 + 复杂度分类器，系统已具备 B/C 路径） |

**辅助线**：
- 工具治理升级：10 工具阶段切分（✅）→ 20-50 分组路由（ADR-0012 B 方案）→ 50+ 动态检索（C 方案）
- 多模态：064 多格式解析（PDF 图片 → VLM 描述）→ 版式敏感文档再评估 ColPali
- 评测自动化：golden 112 题人工 → LLM-as-judge / NLI 自动扩标注（目标 500+ 题免人工）
- 多 Agent：**当前不需要**（单 Agent 场景，业界记分卡 8 分 << 25 分门槛）；触发信号 = 工具超 20 或跨领域
- GraphRAG 全局查询：知识库出现"主题级/全局"问题需求时再评估社区摘要

## 三个已知局限（诚实边界，面试主动交代）

1. **无 Adaptive 复杂度路由**：简单问题也走全检索（浪费 token、延迟偏高）——升级主线 ③
2. **反思/幻觉判断靠提示词**：不如 Self-RAG 训出来的稳定；NLI 相关评测未达 kappa 0.7 门槛
3. **单机单 Agent 规模**：无分布式/多租户/多 Agent 协作能力——触发条件满足才升级

## 面试话术（开场定位，30 秒）

> "我的项目是 Agentic RAG——Modular 架构承载、Advanced 检索链打底。检索层有改写、HyDE、三通道 RRF 融合、语义重排（0.9905）；Agent 层让 LLM 自主决定检索充分性和工具调用（10 工具按阶段分组，反思不充分自动重检）；记忆做到进化 v2（类型化衰减、冷记忆降权、冲突消解）。和 GraphRAG/Self-RAG/Adaptive RAG 的差异我清楚：图谱只做三通道之一（全局问题答不了）、反思是提示词版不是微调版、还没有按复杂度路由——这三条正是我的演进主线。核心认知：**先有评估闭环（改坏能发现、改好有证据），再谈架构升级**——我的每个演进决策都有数据支撑，不预设成功。"

## 验收标准（本 ADR 无代码，用于口径一致性）

- [ ] 面试/简历引用本项目类型时，一律用"Agentic RAG（Modular 架构 + Advanced 检索链）"口径
