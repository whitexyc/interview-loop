# ADR-0004 — 重排（Rerank）模型与截断策略决策

- 状态：已采纳（当前实现）；截断值 500 → **250（module-044 WP1 已验证，见下）**
- 日期：2026-08-09
- 背景：简历 1.4 节深挖过程中，围绕"语义重排"逐词核对 `rag/reranker.py`，沉淀模型选型、截断策略、分数特性三项决策；其中"250 字符截断值"为待验证项，由用户后续补测。

## 决策 1：使用 CrossEncoder 架构 + bge-reranker-v2-m3

**当前实现**：`rag/reranker.py` 用 `BAAI/bge-reranker-v2-m3`（本地 `models/bge-reranker-v2-m3/`，model.safetensors ~2.17GB），BGE 系列**分类式** CrossEncoder，sigmoid 输出相关性概率，CPU 实测 ~515ms/对。

**为什么 CrossEncoder**：向量检索（`retriever.py`）是 Bi-Encoder——query/doc 独立编码、速度快但精度有限；CrossEncoder 把两者拼接成一句话（`[CLS] query [SEP] doc`）做完整交叉注意力，直接输出相关性分数，精度更高但慢。故只对混合检索召回的 Top-20 精排取 Top-5。

**为什么不主动讲换模型史**：`models/` 目录另存 Qwen3-Reranker-0.6B（生成式，实验未走通）、all-MiniLM-L6-v2（历史 embedding）。简历 07 只写"语义重排"+"嵌入/重排全本地离线推理"，未提换模型——面试不主动讲未走通的实验，避免被追问"为什么不用"。

## 决策 2：重排内容截断到 500 字符（_MAX_PAIR_CHARS=500）

**背景**：CrossEncoder 按 **batch 内最长序列填充**；知识库父块可达数万字符（无 ## 标题文档整篇入库），近满长上下文使单次 rerank 从 ~0.5s 飙到 ~200s（实测 2 pair 201s），阻塞真实链路。

**选数依据（500/1000/2000 对比）**：

| 截断 | 内容量 | 实测表现 |
|---|---|---|
| 500 | 中文 ≈500 字（5-6 句、半页 A4）；英文 ≈80-90 词 | 2 pair ~2.1s，6 pair ~6s，分数 **0.989** |
| 1000 | 中文 ≈1000 字（约 1 页 A4） | 分数 **0.991**——精度几乎无提升、耗时翻倍 |
| 2000 | 中文 ≈2000 字（约 2 页 A4） | 耗时线性涨，精度增益趋零 |

**结论**：重排只需判断"文档与问题是否相关"，相关信号集中在前 500 字（标题+开头段落）；超过 500 边际收益骤减、边际成本线性涨，500 是"精度-成本"拐点。候选已由召回层筛过一轮，丢后段信号影响小。

## 决策 3：接受"分类式打分压缩效应"（分数普遍接近 1.0）

**现象**：rerank_score 普遍在 0.85~0.99 高位区间（如 0.991 vs 0.989）。

**原因**（`reranker.py:15-16` 注释原话"分数接近 1.0 时排序仍正确，区分度低是已知特性"）：
1. 模型是二分类器（相关/不相关），sigmoid 输出概率——明显相关 → 接近 1.0
2. 进重排的候选已被检索层筛过（都是相关的），垃圾进不来 → 分数挤在高位
3. 排序只看相对大小不看绝对高低 → 0.991 vs 0.989 序仍正确，不影响 Top-5 选择

**展望**：若将来做"分数阈值过滤"（如 <0.7 丢弃低质文档），必须先做概率校准（Platt scaling），否则阈值判断无意义；当前只用于排序，不阻塞。

### 决策依据

- 250 相关文档分数 0.9907~0.9988，全部 ≥ 0.98；与 500 差值 ≤ 0.002（噪声级）
- 6 pair 耗时 5.455s vs 9.900s，下降 44.9%（2 pair 同理降 47.6%）
- 三档排序 6/6 完全一致（重排只取 Top-5、排序只看相对大小——决策 3 特性，弱相关文档绝对分数虽随截断缩短下降（如 g1/doc2 0.2195→0.0535），但排序位置不变，不影响 Top-5 选择）
- 局限（如实记录）：benchmark 文档为构造子块（非线上真实父块），绝对分数非生产值；上线后建议观察真实链路耗时变化
