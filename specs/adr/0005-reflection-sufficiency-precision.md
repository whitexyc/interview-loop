# ADR-0005 — 反思充分性判断精确化：五层方案

- 状态：**层 0-3 已实现（module-044，2026-08-09）；层 4 留待标注数据积累后另行模块**
- 日期：2026-08-09
- 背景：`agent/reflector.py::check_sufficiency` 的充分性判断目前**只要文档非空就完全由 LLM 说了算**（读前 5 篇摘要返回 `{"sufficient": bool, "reason", "rewritten_query"}`）。用户质疑：LLM 主观判断可靠吗？如何更精确判断反思是否充分？本 ADR 记录讨论结论——把"LLM 单点主观判断"升级为"客观信号 + 主观判断 + 评测闭环"的复合系统。
- 姊妹篇：与 ADR-0003（intent 校验）方法论一致（分数口径 + 不对称投放 + 小分类器治本），形成闭环。

## 现状边界（先诚实交代）

只要 `docs` 非空，`sufficient` 就是 **LLM 全权负责的主观判断**，没有客观分数参与。系统在 LLM 之外有三道**非 LLM 兜底闸门**：

| 闸门 | 机制 | 生效场景 |
|---|---|---|
| ① 空文档短路 | `docs=[]` → 直接判不充分，不调 LLM（reflector.py:142-144） | 检索不到内容 |
| ② 文档数阈值 | round 0 ≥3 篇 → 跳过反思直接生成（`_MIN_DOCS_SKIP_REFLECT=3`） | 数量足够时根本不问 LLM |
| ③ 超时/失败兜底 | 10s 超时 / LLM 异常 → 默认充分防死循环；30s 预算封顶 | LLM 不可用时 |

准确表述：**"LLM 是充分性判断的主闸门，但不是唯一闸门"**——三道代码闸门处理"明显不充分（空）""明显充分（数量够）""LLM 不可用（超时）"三类边界，中间地带（文档非空但质量存疑）才交给 LLM 语义判断。

## 五层精确化方案（按成本从低到高）

### 层 0 · 评测闭环（必须先做，否则改进无法量化）

- 建**充分性标注集**：从 golden 集取问题 → 跑真实检索拿文档 → 人工标"这份检索结果够不够回答"（充分/不充分）
- 指标：充分性判断的 **Accuracy / Precision / Recall**——重点看 **Recall**（漏判"不充分"会导致硬答，最致命）
- 复用 eval_runs 表版本化回归（`eval_type='sufficiency'`），改任何一层后跑分对比

### 层 1 · 分数硬闸门（最值得先做，零成本，复用 module-035 口径）

**用客观检索分数做第一道判断，不靠 LLM 感觉**：

```
top-1 绝对余弦 < 0.4 → 直接判不充分（连 LLM 都不用问）
文档数 < 2           → 直接判不充分
```

- 绝对余弦口径**项目里已有**：embedding 存库/查询均 L2 归一化，点积=cosine，跨查询可比（module-035 动态 K 修复后的正确口径）
- LLM 只处理分数达标的模糊地带——预算不对称投放

### 层 2 · LLM 内部强化（改 prompt，成本低）

- **few-shot**：prompt 里给"充分"/"不充分"的真实正反例，比纯规则描述判得更稳
- **chain-of-thought**：先让 LLM 列出"回答这个问题需要哪些信息点"，再逐点比对文档是否覆盖——从"凭感觉"变成"结构化比对"
- **自洽性检查**：同 query 两次判断（不同温度），结果不一致 → 保守回退（判充分，防漏检）

### 层 3 · 多信号融合（LLM 只判模糊地带）

分数信号（客观）+ LLM 语义判断 + 文档数规则 → 加权/投票：

- 分数高 + LLM 充分 → 充分
- 分数高 + LLM 不充分 → 走 LLM（它看到了规则看不到的语义缺口）
- 分数低 → 直接不充分（不调 LLM，省成本）

这正是 ADR-0003 L2"不对称确认"思路的复用——**预算不对称投放，LLM 只处理真正模糊的样本**。

### 层 4 · 小分类器治本（长期，复用 ADR-0003 L4）

- bge-m3 embedding + 逻辑回归训练"充分性分类器"，输出**校准过的概率**——彻底摆脱"LLM 自报判断不可信"
- 推理毫秒级、本地跑，与 intent 分类器共用同一套基建
- 需要标注数据：层 0 的标注集即训练集

## 方法论闭环（面试可串讲）

| 复用点 | 来源 | 用途 |
|---|---|---|
| 绝对余弦口径 | module-035（动态 K 恒 K=1 教训） | 层 1 分数硬闸门 |
| 不对称投放 | ADR-0003 L2 | 层 3 多信号融合 |
| 小分类器治本 | ADR-0003 L4 | 层 4 充分性分类器 |

同一个"分数口径 + 不对称校验 + 小分类器"方法论贯穿全项目，面试能串起来讲是很大的加分。

## 推荐实施顺序

1. 层 0（半天）：建充分性标注集 → 跑出 baseline（没有它后面都是盲人摸象）
2. 层 1（零成本）：分数硬闸门，直接砍掉 LLM 的明显误判
3. 层 2（低）：prompt 强化，few-shot + CoT 信息点比对
4. 层 3（中）：多信号融合，让 LLM 只判模糊地带
5. 层 4（长远）：标注数据够了换小分类器，治本

## 实施状态（2026-08-09 module-044）

- **层 0 ✅**：`eval/golden_sufficiency.py` —— 12 条充分性标注集（充分/不充分各 6，含"完全不沾边""主题错位"两类漏判场景；每条 2 篇文档，兼容层 1 数量闸门不短路真实评测）+ Accuracy/P/R/F1/混淆矩阵（重点 insufficient Recall）+ eval_runs `eval_type='sufficiency'` 版本化落库 + `--fixture` 模式（启发式判断器，不依赖 DB/LLM）。测试 `tests/test_golden_sufficiency.py` 12 用例全过。
- **层 1 ✅**：`check_sufficiency` 分数/数量硬闸门 —— 文档数 < 2 或 top-1 `abs_cosine` < 0.4 → 直接判不充分（零 LLM）；字段缺失/异常走 LLM 不误杀。
- **层 2 ✅**：`_CHECK_PROMPT` 强化 —— few-shot 正反例 + CoT 信息点比对；自洽性检查配置开关 `PW_SUFFICIENCY_SELF_CHECK_ENABLED`（默认 False，开启时两温度各判一次、不一致保守充分）。
- **层 3 ✅**：多信号融合 —— 分数达标才问 LLM，LLM 只判模糊地带；LLM 判不充分仍尊重语义走 rewritten_query。
- **层 4 ❌ 本模块不做**：标注数据不足（层 0 标注集仅 12 条），数据积累后另行模块（与 ADR-0003 L4 同理）。
- 实测待办：层 0 真实模式 baseline（reflector + LLM）需 LLM 环境，模块开发期未跑；fixture 模式已验证管线，上线后补跑真实 baseline 并进入版本化回归。

## 面试话术

> "精确判断反思充分性，我的思路是五层：先建充分性标注集和评测闭环，否则改进无法量化；加分数硬闸门——top-1 绝对余弦低于阈值直接判不充分，不靠 LLM 感觉，这个口径 memory 里已经踩过坑修好了；再强化 LLM prompt——few-shot 正反例、让 LLM 先列信息点再比对；更进一步是多信号融合，分数达标才问 LLM，让 LLM 只判模糊地带；长期用 bge-m3 + 逻辑回归训一个充分性分类器，输出校准概率。核心是让'客观分数'和'主观语义'各管一段，LLM 不是唯一闸门。"

> 追问 1："当前为什么还够用？"——反思调用成本可控（一次输入约 800-1000 token、输出 50-150，超时围栏 10s，最多调 2 次），且空文档短路 + 文档数跳过已覆盖大部分边界；语义充分性本质是模糊判断，LLM 是自然选择，代价是时间而非正确性。

> 追问 2："层 1 阈值 0.4 怎么定的？"——参照 memory 动态 K 的 `memory_recall_min_score` 阈值口径（module-035 验收），具体值需用层 0 标注集做阈值扫描（precision/recall 曲线）确定，先用经验值 0.4 起步。
