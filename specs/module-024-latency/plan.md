## 2. 需求描述

### 2.1 需求来源

- 来源类型：发散路线图 P2-10 + 用户确认
- 原始描述：检索链路存在延迟问题：round 0 向量检索超时无降级（整链路失败）、HyDE 结果不缓存（每次重复调用）、整链路无总预算（最坏 85s）。

### 2.2 用户故事

```
作为 RAG 系统用户
我想要 检索响应更快、超时更稳
以便 最坏情况不至于卡死，常规情况更快返回
```

### 2.3 验收场景（BDD 格式）

```
场景 1：round 0 超时降级
  假设 向量检索超时（>15s）
  当 round 0 执行
  那么 不整链路失败，降级为仅图结果继续

场景 2：HyDE 缓存
  假设 同一 query 检索两次
  当 第二次走 HyDE
  那么 命中缓存（不重复调 LLM）

场景 3：整链路预算
  假设 检索链路超时（>30s）
  当 到预算上限
  那么 强制进入生成（不无限等待）

场景 4：提前终止
  假设 第一轮反思 sufficient
  当 循环执行
  那么 立即返回（不再第二轮）
```

### 2.4 非功能需求

| 类别 | 要求 |
|------|------|
| 兼容性 | _retrieve 返回格式不变 |
| 延迟 | 常规查询显著加速 |
| 不回归 | 检索质量不下降（评估基线对比） |

## 3. 技术方案

### 3.1 涉及文件

| 文件路径 | 操作类型 | 说明 |
|----------|----------|------|
| `ai_service/rag/engine.py` | 修改 | round 0 降级 + HyDE 缓存 + 总预算 + 提前终止 |

### 3.2 数据库变更

无（HyDE 缓存用 Redis）。

### 3.3 业务逻辑说明

#### 核心流程（engine._retrieve 改造）

```
1. round 0 超时降级:
   当前: asyncio.gather(vector_task, graph_task) 无降级
   新:   用 asyncio.gather(..., return_exceptions=True)
         - 向量检索超时/失败 → 降级为仅图结果
         - 图检索失败 → 降级为仅向量结果
         不再整链路崩溃

2. HyDE 缓存:
   hyde_key = f"rag:hyde:{hash(query)[:12]}"
   先查缓存 → 命中直接返回
   未命中 → LLM 生成 → 写入缓存（TTL 300s）
   失败/超时 → 降级用原始 query（现有行为）

3. 整链路预算:
   deadline = asyncio.get_event_loop().time() + 30
   每轮循环检查是否超时
   到点 → 用已收集的 docs 进入生成（不强制再多检索）

4. 提前终止强化:
   round 0 反思 sufficient → 立即 break（现有逻辑已部分实现）
   补充: 若 round 0 已收集到足够文档（如 ≥3 篇），可跳过第二轮
```

#### 关键设计决策

| 决策 | 说明 |
|------|------|
| round 0 用 return_exceptions | 一路失败不影响另一路（与混合检索降级哲学一致） |
| HyDE 缓存独立 key | 不污染检索结果缓存 |
| 30s 总预算 | 平衡质量与延迟 |
| 提前终止阈值 | round 0 ≥3 篇文档即跳过第二轮 |

### 3.4 异常处理

| 异常场景 | 异常类型 | 处理方式 |
|----------|----------|----------|
| round 0 向量超时 | TimeoutError | 降级为仅图结果 |
| HyDE 缓存不可用 | Exception | 不缓存，正常生成 |
| 总预算超时 | — | 用已收集 docs |

```bash
cd ai_service

# 2. HyDE 缓存测试（两次检索，第二次命中缓存）

```

### 4.2 预期输出

```
# HyDE 缓存: 第二次检索日志显示 "HyDE 缓存命中"
# 整链路: 常规查询耗时明显下降
# 评估: hybrid Hit@5 不下降（≥ 0.91 基线）
```

### 4.3 失败诊断方法

| 失败现象 | 可能原因 | 排查步骤 |
|----------|----------|----------|
| 降级不生效 | gather 未用 return_exceptions | 检查 round 0 逻辑 |
| HyDE 不缓存 | cache 未接入 | 检查 hyde_key |
| 检索质量下降 | 提前终止过激 | 检查阈值 |

## 6. 风险点与注意事项

### 6.1 已知风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 提前终止过激 | 检索质量下降 | 低 | 阈值保守（≥3 篇才跳过） |
| 总预算太小 | 质量受损 | 低 | 30s 平衡 |

### 6.2 技术注意事项

- [x] round 0 降级不改变返回格式
- [x] HyDE 缓存 key 独立
- [x] 提前终止保留现有 sufficient 逻辑
- [ ] 需验证 gather return_exceptions 与现有合并逻辑兼容

### 6.3 开发建议

- 优先实现 round 0 降级（正确性）→ HyDE 缓存 → 总预算 → 提前终止
- 用评估基线对比质量不下降
