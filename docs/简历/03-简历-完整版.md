### 1. Agentic RAG 技术文档知识库问答系统（2026.07 - 至今）· 大模型应用开发工程师（全栈）

**项目背景**：面向技术笔记分散、无法直接交互问答的痛点，将 **124 篇技术笔记（累计约 156 万字、平均每篇 1.3 万字，覆盖 JVM、并发、分布式等领域）** 转化为可交互、引用可溯源的 Agentic RAG 技术文档知识库，**支持任意用户以自然语言问答**，实现文档管理、混合检索、Agent 智能问答、多层记忆的完整链路。本人主导整体架构设计、检索质量与系统稳定性的持续优化，并建立可量化、可回归的评估体系驱动每一轮改进。

**技术架构**：Spring Boot 3.2 · FastAPI · React 18 · PostgreSQL(+pgvector/Apache AGE) · Redis · LangChain/LangGraph · bge-m3/bge-reranker 本地模型 · JWT

**主要职责**：

1. **Agent 能力链路**：构建 Agentic Self-RAG 流水线（意图路由 → 混合检索 → 语义重排 → 自我反思纠错 → 流式生成）；意图路由采用 LLM 零样本分类，输出解析失败或值不在白名单时保守回退到知识库检索，宁多检不漏检；检索结果不充分时自动改写查询重试；进一步落地 Agent 工具化（ReAct 思考-调用-再思考循环 + 10 个可注册工具），工具调用轨迹经 SSE 实时推送前端展示，回答附引用溯源；幻觉检测采用 HHEM 专职裁判（LLM 拆句 + 专职检测模型逐句判分，解决"写答案的 AI 批自己卷子"的同源验证问题）。

2. **三通道混合检索与评估体系**：融合关键词全文、语义向量、知识图谱三路召回，加权归一化统一分数——中文检索通过 jieba 预分词落库并建倒排索引，解决默认分词下的中文空召回问题；文档采用"章节级父块 + 300 字子块"两级分块，小块检索更精准、大块回答更完整；分诊式查询改写（FTS 术语静态分诊判"要不要改写"→ 模糊 query 才改写 → 保真预检余弦回退 → 原/改写并行检索择优，改错可回退）；自建 112 题 golden 评测集与 Hit@k/MRR 指标体系，实现版本化回归（每次评估记录代码版本与配置快照），让调参可复现、可防退化。三通道融合后 Top-5 命中率 **0.97**（112 题实测 0.9714，105 题有效口径）。进一步将评估体系从检索质量扩展到 **Agent 行为**：工具调用明细落库（trace_id/参数/成败/耗时）+ 36 条任务级评测集（覆盖单轮/多轮/闲聊/实时/重检/记忆六类路径）+ 三层指标（任务完成率 pass^1/pass^3、工具调用正确率、成本步数），判定全确定性（不用 LLM 评 LLM）；**首跑即抓到真实盲区**——generate_answer 在 agent 循环内死锁（阶段切分只暴露检索工具、推进条件却要求先调生成工具），A/B 双配置定位修复后真实轨迹出现生成调用且任务通过。

3. **多层记忆与用户上下文隔离**：设计长期/短期/会话三层记忆——长期记忆由 LLM 自动抽取关键事实并按重要度过滤后留存、短期记忆带过期时间滚动更新、会话记忆逐条持久化且内容去重幂等；系统面向多用户，**每个用户拥有独立记忆上下文、互不串扰**（JWT 登录身份为主、匿名降级 IP 兜底），记忆与知识库双向隔离（记忆不污染知识库、检索只查本用户记忆）；记忆写入采用异步落库，不阻塞回答，普通聊天、流式与 Agent 端点全链路接入，实现跨会话上下文连续。

4. **可靠性工程**：为整链路设计 30 秒时限预算强制封顶与每步独立级联超时，超时自动降级不卡死；多供应商 LLM 自动降级链，单家 API 故障不中断服务；检索缓存采用参数化键并随数据变更自动失效（命中 3ms）；嵌入与重排模型全本地部署，实现完全离线推理；并发检索经双连接并行改造后，16 路并发与串行结果完全一致。
